# Quality check 2026-11-01

The ten quality rules checked against the code, with evidence. Python 3.14.5, PyTorch 2.15.0 (CPU
build, fresh `.venv`), Windows 11, Intel Core i7-13700H. The only external calls are the dataset
download and the gloo process group on 127.0.0.1.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | fixed | The download has a 60 s timeout and is refused unless size and SHA-256 match (`data.py` `download`); it is not retried (a manual `dtlab data` re-run starts over). Child-process failures propagate: `mp.spawn(join=True)` raises, the CLI turns `ValueError`, `FileNotFoundError` and `RuntimeError` into exit 2 (`cli.py` `main`). No `except: pass` or swallowed errors (`grep -rn "except" src`: one handler, which prints and returns 2). Found: `init_process_group` had no timeout, so a rank that died or hung left the others blocked for gloo's 30-minute default. Now `PG_TIMEOUT` = 5 minutes in `train.worker` and `verify._check`. |
| 2 | Writes safe to retry | fixed | The dataset is written to a `.part` file and renamed only after the size and hash match (`download`). Found: run summaries were written in place with `write_text`, so a crash mid-write left a truncated JSON that a later reader would fail on. Now `write_json_atomic` (temporary file, then `replace`) for train, scale and verify results; re-running a run replaces its file whole (`test_json_results_are_replaced_whole`). |
| 3 | No race conditions | pass | No threads. Ranks are separate processes that share nothing but collectives; rank 0 alone writes the summary. `free_port` binds port 0 and closes it before gloo binds it again, so another process could take the port in between; the result is a clear rendezvous error, not a wrong result (known limitation below). |
| 4 | Don't trust the clock | pass | Every duration uses `time.perf_counter()` (`train.py` `_train`, `comm.py` `GradientAllReducer.sync`), with `torch.cuda.synchronize` before reading it on the GPU. No timestamps are stored or logged. |
| 5 | Read before changing | pass | APIs used exist in the installed PyTorch 2.15.0 (`init_process_group(timeout=timedelta)`, `isend`/`irecv`, `fused=` AdamW); mypy `--strict` passes against them. The code sets `USE_LIBUV=0` for gloo and reads no environment variables or config files. Every path in the README exists. |
| 6 | Never break compatibility | pass | The run summary JSON keeps every field; no field was renamed or removed. The dataset is pinned to one commit, size and hash. |
| 7 | One source of truth | fixed | `.tmp/data/TinyStories-valid.txt` is a cached copy of the pinned Hugging Face file, rebuilt by `dtlab data` (which replaces a cached file whose hash is wrong, `test_download_replaces_a_cached_file_with_the_wrong_hash`). Found: training trusted the cached file when its size matched, so a same-size but altered file would have been trained on. `load_tokens` now checks the SHA-256 too (`test_tinystories_file_with_the_right_size_but_wrong_bytes_is_refused`). Versions: `requires-python >=3.11`, README "Python 3.11+", CI 3.12; the README now says the measured runs used PyTorch 2.14 and the tests also pass on 2.15.0. |
| 8 | Small changes, no secrets, validate input | pass | Secret scan (`grep -rniE "api[_-]?key\|token\s*=\|password\|secret\|PRIVATE KEY"`): no matches. CLI options and model shapes are validated with clear errors (`config.py` `ModelConfig`, `TrainConfig`, `cli._safe_out`); a bad `--world-sizes` list exits 2 (`test_scale_rejects_a_bad_world_size_list`). No new dependency. |
| 9 | Tests that can fail | fixed | No tautologies, skips or assertion-free tests. Mutation table below: 5 of 11 killed before; all 11 killed after. One survivor was a real blind spot: AdamW is almost invariant to a constant gradient scale, so dropping the division by N in the all-reduce left every loss within 1e-4 of the single-process run. A new test checks the synchronised gradients directly. |
| 10 | Re-verify | pass | `bash .tmp/check.sh`: ruff `All checks passed!`, `24 files already formatted`, mypy `Success: no issues found in 14 source files`, `57 passed in 249.48s`, pip-audit `No known vulnerabilities found`, `distributed-training-lab: OK`, `CHECK PASS`; `dtlab verify --world-size 4`: PASS. CI result is recorded in the commit's workflow run. |

killed), plus the new SHA-256 check's mutant killed.

## Known limitations

- `free_port` can race with another process taking the port before gloo binds it; the run then
  fails at rendezvous with an error and can be re-run.
- The dataset download is not retried automatically.
- Multi-GPU (NCCL) and multi-node runs are not tested (as in the README scope).
