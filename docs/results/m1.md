# M1 results

All numbers below come from runs on one machine: Intel Core i7-13700H, 13.7 GB RAM, NVIDIA
RTX 4050 Laptop GPU (6 GB, driver 596.36), Windows 11, Python 3.14, PyTorch 2.14.1 (CUDA 13.0
build), gloo backend. Other builds ran on the same machine at the same time, so timings are noisy.
Raw JSON for each run is written to `.tmp/runs/` (git-ignored).

## What was measured and what was not

| Claim | Measured here | Not measured |
|---|---|---|
| Training on 1, 2 and 4 ranks | 1, 2, 4 gloo processes on the CPU; 1 rank on the RTX 4050; 2 ranks sharing the RTX 4050 | 2 or 4 physical GPUs, NCCL, multiple nodes |
| DDP replicates the model | parameter difference across ranks after training is exactly 0 in every run | |
| Gradients averaged with all-reduce | hand-written ring all-reduce and gloo all-reduce, both equal to one process on the whole batch | overlap of all-reduce with backward (M3) |
| Cost | step, compute and all-reduce time, tokens/s, CUDA peak memory | a profiler trace (M3), multi-GPU memory per rank |

## CPU strong scaling (Measure)

```bash
dtlab data
dtlab scale --world-sizes 1,2,4 --model scaled --data tinystories --steps 15 \
  --global-batch 32 --seq-len 128 --threads-per-rank 2 --warmup-steps 3 --name cpu-scale
```

`scaled` model (4,837,376 parameters, 77.4 MB of parameters, gradients and AdamW state per rank),
TinyStories validation file at the pinned commit, byte tokens, global batch 32 x 128 tokens, AdamW
lr 3e-3, seed 0, 2 threads per rank. Means exclude the 3 warm-up steps.

| Ranks | Step (ms) | Compute per rank (ms) | All-reduce (ms) | Tokens/s | Speedup | Efficiency | Final train loss | Held-out loss |
|---|---|---|---|---|---|---|---|---|
| 1 | 15,392 | 14,382 | 0 (not needed) | 266 | 1.00x | 100% | 3.1447 | 3.1102 |
| 2 | 8,341 | 7,220 | 496 | 491 | 1.85x | 92% | 3.1447 | 3.1102 |
| 4 | 2,208 | 1,794 | 235 | 1,855 | 6.97x | 174% | 3.1447 | 3.1102 |

All three runs reach the same losses (first loss 5.6562, final 3.1447, held-out 3.1102) and end
with replicas that differ by exactly 0. Each step all-reduces 6 buckets (19.3 MB of gradients).

## GPU runs

```bash
dtlab train --world-size 1 --device cuda --model scaled --data tinystories --steps 300 \
  --global-batch 32 --seq-len 128 --lr 1e-3 --warmup-steps 20 --name gpu-w1
dtlab train --world-size 2 ... --name gpu-w2   # same options, two ranks sharing the one GPU
```

| Run | Step (ms) | Compute per rank (ms) | All-reduce (ms) | Tokens/s | CUDA peak memory per rank | Loss 5.656 to | Held-out loss |
|---|---|---|---|---|---|---|---|
| 1 rank, RTX 4050 | 227.5 | 220.0 | 0 | 18,006 | 514 MB | 3.077 | 3.054 |
| 2 ranks sharing the RTX 4050 | 522.5 | 139.2 | 374.3 | 7,840 | 295 MB | 3.081 | 3.058 |

The 2-rank GPU run proves that the CUDA path (gradients staged through host memory for gloo)
keeps replicas identical; it is not a scaling result, since both ranks share one GPU.

## Analyze

- **Equivalence holds.** Because every rank takes a slice of one seeded global batch and the
  all-reduce divides by N, 1, 2 and 4 ranks perform the same optimisation; losses agree to about
  5e-7 (float32 summation order), and the held-out loss is the same to four decimals.
- **The CPU efficiency above 100% is not real scaling.** Two causes, both measured:
  1. Load on the machine changed during the sweep: the same 1-rank configuration measured
     15.4 s per step in the sweep and 7.8 s per step in a later run (`--steps 6`).
  2. Per-token cost depends on the local batch: at 1 rank with 2 threads, local batch 8 ran at
     707 tokens/s and local batch 32 at 526 tokens/s (later probe runs), so splitting the batch
     also made each rank's work cheaper per token.
  The defensible numbers from this sweep are the all-reduce costs (0.50 s at 2 ranks, 0.24 s at
  4 ranks for 19.3 MB) and the equal losses, not the speedup.
- **The GPU is launch-bound on this machine.** A probe measured about 173 µs per tiny CUDA kernel
  launch while other work ran, and 2.5 TFLOPS on a 4096 x 4096 float32 matmul, so a
  4.8M-parameter step made of many small kernels is dominated by launch overhead.
- **Defect found and fixed:** PyTorch DDP over gloo with CUDA tensors crashed on Windows with an
  access violation (exit code 3221225477). The CLI now refuses `--strategy torch --device cuda` on
  Windows with a clear message; the PyTorch DDP comparison runs on the CPU.

## Improve

- AdamW uses the fused CUDA kernel on GPU runs. Re-measured on 2026-10-31 with
  [`fused_adamw_probe.py`](fused_adamw_probe.py) (1 rank, RTX 4050, `scaled` model, TinyStories,
  32 x 128 tokens, 20 steps per variant back to back in one process, first 3 excluded): mean step
  78.3 ms with the default AdamW and 71.1 ms with `fused=True` (1.10x). Raw output:
  [`fused-adamw-2026-10-31.log`](fused-adamw-2026-10-31.log). An earlier, unlogged probe figure was
  removed because no log of it was kept.
- With one rank no all-reduce is done (the first GPU run spent 230 ms per step copying gradients
  to host memory and back for nothing).

## CI-only

GitHub Actions (ubuntu, Python 3.12, CPU PyTorch) runs lint, the 48 tests, `dtlab verify` on 4
ranks and a 1/2/4-rank run on generated data whose replica and loss equality are asserted and
printed as `::notice` annotations, then the audit. CI has no GPU; the GPU numbers above are local
only. Nothing needs Docker.

## Reproduce and clean up

No model files are written: weights live only in memory during a run, and only the JSON summary is
kept. The dataset is the TinyStories validation file at commit
`f54c09fd23315a6f9c86f9dc80f725de7d8f9c64` (SHA-256 `94e43181...cb38b4`), downloaded by
`dtlab data` into `.tmp/data/`; delete that folder to remove it. Seeds: data and init seed 0
(ranks other than 0 initialise with seed `rank` and are overwritten by the broadcast).
